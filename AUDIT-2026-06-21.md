## Method & Evidence Constraints (bounds every claim)

- Live fetches used WebFetch against production. WebFetch renders to markdown, so it reliably exposes HTTP status, H1/H2/body text, redirect behavior, and the raw text of /robots.txt, /sitemap.xml, /llms.txt — but it STRIPS the <head> (title/meta/canonical/robots-meta) and inline JSON-LD scripts.
- curl -I (raw headers), Playwright, and git were unavailable here (outbound network + tools sandbox-denied). I could not directly observe live response headers, live <link rel=canonical> tags, or live JSON-LD bytes.
- Mitigation: /robots.txt, /sitemap.xml, /llms.txt are static files in /public; I read them in the repo AND fetched them live — they matched, proving the deployed artifact tracks the repo for static assets. For head/canonical/schema I treat the repo metadata objects + JSON-LD literals as authoritative for what Next renders, and cross-check page BODIES live for drift. Head/schema claims cite repo source file + line.
- Items I could NOT falsify live are marked [UNVERIFIED-LIVE] and listed in a dedicated section.
